# 02 — UI

## Design language
Clean, focused, keyboard-driven. The app has two moods:
- **Test Mode** — minimal, calm, mimics the real Digital LSAT. No correctness
  feedback, no AI, no analytics while the clock runs. Just question + tools + timer.
- **Study Mode** — data-rich. Dashboards, explanations, AI coach, error log.

Light/dark themes. Everything reachable by keyboard (A–E to answer, F to flag,
←/→ to navigate, etc.).

## Question-taking screen (Test Mode) — most important screen
Two-pane for RC (passage left, question right), single-pane for LR. Tools mirror
the real Digital LSAT.
```
┌──────────────────────────────────────────────────────────────┐
│ PT 73 · Section 2 · Q 14 of 26      ⏱ 22:14   ⚑Flag  [Hide⏱] │
├───────────────────────────────┬──────────────────────────────┤
│  STIMULUS                      │  Which one of the following,  │
│  Editorial: The city council  │  if true, most weakens the    │
│  claims the new tax will       │  argument above?              │
│  reduce traffic. However...    │  ┌──┐                         │
│  [highlightable, 3 colors]     │  │A │ The tax applies only…   │
│                                │  ├──┤  ⊘ (eliminated)         │
│                                │  │B │ Most commuters already… │
│                                │  ├──┤                         │
│                                │  │C │ The council's data…  ◉  │
│                                │  ├──┤                         │
│                                │  │D │ Traffic studies show…   │
│                                │  ├──┤                         │
│                                │  │E │ The new tax is lower…   │
│                                │  └──┘                         │
├───────────────────────────────┴──────────────────────────────┤
│  [◀ Prev]  ●○○○●○○○○●○○○◉○○...  (●=flagged)         [Next ▶]  │
```

Tools: per-choice **eliminator** (strike), **highlighter**, **flag**, **hideable
timer**, **question navigator** strip. Fully keyboard-operable.

## Blind Review screen — the differentiator
After timing ends, before revealing answers:
```
┌──────────────────────────────────────────────────────────────┐
│  BLIND REVIEW — PT 73 S2     No timer.  Redo flagged + unsure. │
│  Q14   Your timed answer: C                                    │
│  ┌────────────────────────────────────────────────────────┐   │
│  │ Take your time. Commit to your best answer now.         │   │
│  │  ○A   ○B   ●C   ○D   ○E                                  │   │
│  │  Confidence: ◉ Sure  ○ Pretty sure  ○ Guessing          │   │
│  └────────────────────────────────────────────────────────┘   │
│                                       [Reveal answer & explain]│
└──────────────────────────────────────────────────────────────┘
```
On reveal: a **2×2 outcome** (timed ✓/✗ × BR ✓/✗) routes the question into the
right bucket (timing drills / concept review+SRS / "lucky, don't trust").

## Analytics screen
Tabs: **By Type** · **Timing** (per-question time heatmap across a section) ·
**Timed vs Blind Review** (the gap chart) · **Difficulty curve** · **Trap
analysis**. Filter: real questions only vs include AI drills.

## Other screens
- **PrepTests:** library of imported tests, completion state, "start full timed
  exam" (multi-section, real timing, section breaks).
- **Drills:** pick type/difficulty/count/timing; real or AI-generated source.
- **SRS:** today's FSRS-due cards.
- **Import wizard:** the PDF → structured-question flow (see 01-architecture §
  ingestion), with the human-verify split view.
- **Settings:** model routing (explain vs generate), timer defaults, theme,
  keyboard map, data export/backup.

## Accessibility / feel
- Full keyboard control; visible focus states.
- The Test-Mode screen deliberately hides streak/score/analytics to avoid anxiety
  during timed work — those live only in Study Mode.
