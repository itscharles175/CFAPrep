## Thesis

StudyVault is a mature local-first study OS where the next frontier is no longer breadth (the 146-task ledger already shipped the data bridge, RAG, AI core, psychometrics, native shell, and UI unification) but TRUST, MEASURABILITY, and DURABILITY of what's already there. The roadmap is gated by three hard truths verified in the tree: (1) the product's #1 promise — "no cloud, works on a plane" — needed merge-gate enforcement; AI-10/GAP-EGRESS now ship the first floor with strict offline LLM guards and a static no-egress CI/release scan. (2) Several flagship subsystems are wired-but-unfired or dormant: BACK-4 now ships the maintenance scheduler tick first floor, while the hybrid retrieval blend is still dead code (useVector=false, no host embedder), the salvage-rewrite flag is unimplemented, and the Windows Job Object crash-cleanup claimed done has no code. (3) Every quality claim (RAG, generation, psychometrics) is unmeasured — there is no eval harness, no determinism contract (the host LLM sets no seed and no response_format), and 90 backend test files plus the Rust supervisor tests never run on a PR. So the spine is: first make the offline invariant unbreakable and turn on what's already built (cheap, high-leverage), then build the measurement substrate that makes every downstream AI/learning improvement provable, then finish the storage substrate so cutover and recovery become safe, and only then pursue the genuinely new capability jumps (adaptive testing, faithful citations, self-filling content, prescriptive forecasting) on a foundation that can prove they help. We respect local-first absolutely: every item degrades gracefully offline, stays single-user, and writes only to disk — and we scrub distributed-systems vocabulary so no contributor grows the in-process host->LSAT mirror into a sync server.

## Themes

### Invariant Defense & Activation

The offline/no-cloud promise and the recurring scheduler tick are now merge-gate-enforced at the first floor; the remaining activation work is turning on wired-but-unfired subsystems such as the salvage loop and hybrid retrieval. These are mostly small, high-leverage, dependency-free moves that protect the product's reason for being and unlock value already paid for.

### Measurement Substrate (prove it works)

Every quality claim downstream — RAG retrieval, generated content, prompts, psychometrics — is currently unmeasured, so improvements are guesses and several candidates are explicitly 'OFF until eval shows lift.' Building the eval harnesses, the host determinism contract (seed + structured output), and wiring the dark test suites into CI is the keystone layer that makes the entire AI/learning roadmap safe and defensible.

### Durable Local Substrate (one safe vault)

On a no-cloud app the user's data has no backup of record, yet the storage abstraction covers 5 of 36 tables, cutover can strand 31 tables and silently collide colon-delimited ids, IndexedDB persistence is never requested (eviction = total silent loss), and the live vault is plaintext at rest. This theme finishes the driver, makes migration loss-safe and verifiable, hardens the substrate against eviction/quota, and adds opt-in at-rest encryption — the foundation any cutover or recovery story must stand on.

### Native Platform as Advantage

Being a Tauri desktop app should be exploited, not merely tolerated: crash-safe sidecar lifecycle (Windows Job Object — claimed done but absent), the native commands the frontend already calls (tray/hotkey/single-instance, which today spawns duplicate sidecars), due-review notifications that guarantee FSRS happens on the due day, and trustworthy boot/port orchestration. These make the offline constraint a feature.

### Capability Jumps (the demo-grade frontier)

Once trust, measurement, and durability hold, pursue the genuinely new things a SaaS app cannot do offline: true adaptive testing (CAT), citation faithfulness, prescriptive forecast attribution, a prerequisite-aware knowledge graph, hands-free/inclusive study, and a coverage-driven self-filling content factory over the user's own materials. Each is sequenced behind the eval/determinism/data gates that make it provably better, not just bigger.
